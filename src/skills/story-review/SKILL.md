# 小说诊断

## 边界

- 默认只读，不修改原文；修改交给 `story-revision` 或 `story-deslop`。
- 先理解题材、目标读者、平台、作者意图和本书文风，不用单一网文公式评价所有作品。
- 区分事实矛盾、可观察的读感问题和个人偏好；没有证据不做市场留存或投稿成绩担保。
- 审查范围必须明确：段落、章节、若干章、全书大纲或全书抽样。抽样不能伪装成全书逐章审查。

## 流程

1. **建立基线**：概括本段/本章实际发生的任务、人物选择和状态变化，避免只摘错句。
2. **跑确定性工具**：文件可用且环境支持时运行相关检查脚本，保留位置、类型和严重度；脚本不可用时说明。
3. **按维度人工复核**：只选择适合本次任务的维度，避免每次输出千篇一律的全量报告。
4. **定位根因**：同一症状尽量追到事件、信息、人物或表达层根因，不重复报十几条同义问题。
5. **排序**：先处理阻断理解或连续性的硬伤，再处理影响主要体验的问题，最后才是可选润色。
6. **给最小建议**：说明改哪里、为什么、修改会影响什么；不直接生成整份替换稿。

## 审查维度

### 开篇与读者承诺
- 核心卖点是否通过行动可见，标题与简介承诺何时兑现。
- 主角是否主动选择，首章是否只有背景说明。
- 章尾问题是否来自已启动的动作。

### 结构、信息与因果
- 场景是否有目标、阻力、选择和结果。
- 谁能知道这件事，视角是否越权；揭示后是否改变行动。
- 转折是否有铺垫，误会是否依赖人物不正常沟通。

### 人物、关系与情绪
- 人物是否用不同策略和声音处理事件。
- 反应是否影响下一句，还是重复脸红、震惊、吐槽和夸赞。
- 关系是否形成新基线；亲密是否由现实选择挣得。
- 严重情绪与轻喜剧切换是否有足够过渡和后果。

### 节奏与语言
- 是否复述同一信息、重复证明同一爽点或拆碎同一瞬间。
- 标题事件是否被过量流程说明挤到章尾。
- 长短句是否服务节拍，重要情绪是否被下一句玩笑冲淡。
- 解释腔和模板句是否损害读感；不要把正常词汇当绝对禁词。

## 输出

### 总体结论
用 2—4 句说明当前最有效的部分和最影响阅读的一个根因。分数仅在请求方有明确评分规则时给出。

### 优先问题
| 位置 | 严重度 | 维度 | 证据 | 根因 | 最小修改建议 |
|---|---|---|---|---|---|

严重度：
- `blocking`：事实冲突、正文截断、核心因果断裂等阻断问题。
- `warning`：明显削弱主要阅读体验的问题。
- `info`：可选优化或风格偏好。

### 有效且应保留
列出 1—3 项，防止后续修改误删本书特色。

### 修改顺序
给出不超过 3 轮的建议：结构/事实 → 人物/信息 → 表达/节奏。只检测时到此停止。

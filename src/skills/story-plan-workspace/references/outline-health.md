# 大纲体检规则

## 严重度

| severity | 含义 | 处理 |
|---|---|---|
| `blocking` | 会阻断开写或导致结构断裂 | 必须修复后才能开写 |
| `warning` | 明显影响阅读体验 | 建议开写前修复 |
| `info` | 可优化项 | 可延后 |

## 问题类型

| type | 检查内容 |
|---|---|
| `hook-density` | 章末无钩子、连续章钩子重复、首卷开篇钩子不足 |
| `pacing` | 连续 3 章无冲突/无变化、高潮位置过晚、卷内节奏单一 |
| `logic` | 因果断裂、时间线矛盾、角色行为缺少动机 |
| `motivation` | 主角/对手目标变化缺少触发事件 |
| `setup-payoff` | 伏笔埋设未回收、回收无铺垫、同章即收 |
| `repetition` | 重复桥段、重复信息、重复情绪 |
| `volume-escalation` | 卷与卷之间关系/信息/舞台/规模没有升级 |
| `chapter-closure` | 每章都强行闭环、章末总结升华、缺少留白 |
| `serial-unit` | 缺少可重复单元或可复用名场面，剧情只能靠一次性事件推进 |
| `relationship-state` | 关系长期停在同一个标签，没有升级/退化条件 |

## 确定性与模型分工

先跑脚本：

- `check-plan-health.js`：空 hooks、重复章名、预算漂移、卷间强度断层。
- `check-foreshadow-parity.js`：悬空伏笔、同章即收。

模型只补：

- 动机是否成立、因果是否顺、节奏是否拖、升级感是否够、支线是否交汇。
- 不要重复报告脚本已经给出的确定性问题。

## 补丁边界

- 补丁只能指向未写章。
- 补丁字段只允许 `summary` 与 `hooks`；不得改卷纲、主线、书名、简介。
- 已写章即使有问题，也只报告、不生成补丁。
- 每个补丁必须说明“为什么这样改”和“影响哪些相邻章”。

## 输出要求

- 每个问题必须能定位到卷/章；全局问题用 `volumeOrder` 缺省、`chapterOrder` 缺省表示。
- `description` 写“发生了什么”，`suggestion` 写“怎么改”，不要混在一起。
- 总体 `summary` 不超过 200 字，先给结论再给 Top3 问题。

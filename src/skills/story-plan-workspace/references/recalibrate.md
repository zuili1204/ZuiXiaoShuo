# 重订走向规则

## 目标

在**不改已写内容**的前提下，把未写章调整到与已写事实、作者新意图一致。

## 输入

- 已写事实：章节正文摘要、已发生事件、角色状态、伏笔状态。
- 未写规划：卷纲、章纲、hooks。
- 作者说明：为什么要重订、必须保留什么、可以放弃什么。

## 处理顺序

1. 划边界：列出已写章与未写章；已写章不进入候选集。
2. 找冲突：作者新意图与已写事实冲突时，先列冲突点，不擅自改设定。
3. 定影响面：从冲突章向后推，标出受影响的未写章、伏笔、角色状态、卷尾钩子。
4. 出差异：只对需要改的未写章输出 `oldHooks` → `newHooks`。
5. 说明连带影响：前后章衔接、伏笔回收、角色动机、卷目标。

## 差异格式

```json
{
  "chapterId": "chapter-id",
  "chapterOrder": 7,
  "title": "章名",
  "oldHooks": ["旧走向"],
  "newHooks": ["新走向"],
  "reason": "触发重订的事实或作者意图",
  "rippleEffects": ["第 8 章开头需要改写承接", "F-03 伏笔回收点后移"]
}
```

## 红线

- 已写章不返回、不写入；解析层直接丢弃。
- 不改书名、简介、主线、卷纲；这些属于 A1/A2，不在 A6 范围内。
- 不借重订之名整卷重写；只改确需变化的章。
- 新走向不得与已写事实矛盾；无法两全时列冲突让作者选。

## 失败处理

- 作者说明与已写事实冲突：输出冲突清单，暂停生成。
- 没有可改的未写章：返回空 `diffs`，说明“当前没有可调整的未写章”。
- 影响面过大（超过未写章 50%）：提示作者这更像“重开新书/大修”，建议走 A2/A3 重新规划。

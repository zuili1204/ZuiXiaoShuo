# 规划工作台

## 不可违反的协议

1. 用户已填事实与禁忌优先，只补空缺或按明确要求重规划。
2. 一次只执行一个阶段；所有结果先作为提案，作者确认后才可由系统落库。
3. 已写正文、摘要和 hooks 只读；A6 只改未写章。
4. 外层统一输出纯 JSON，不用 Markdown 代码块：

```json
{"stage":"seed","baseRevision":"rev-...","payload":{},"warnings":[]}
```

5. `stage` 回传请求阶段，`baseRevision` 原样回传；字段与枚举以 `references/proposal-contracts.md` 和校验脚本为准。
6. 信息不足时用 `warnings` 标出【假设】【缺口】【冲突】【风险】，不编造已发生事实。

## 阶段路由

| 请求 | stage | 只做什么 |
|---|---|---|
| A1 完整立项 | `seed` | 书名、题材、梗概、简介、角色、世界锚点、卖点、基调、读者 |
| A1+ 单块规划 | `seed-assist` | 只给指定字段可直接回填的候选建议 |
| A2 主线分卷 | `master` | 全书主线和卷级规划，不写章级事件 |
| A3 卷章纲 | `volume-chapters` | 只处理指定卷的未写章骨架 |
| A4 章细纲 | `chapter-detail` | 只细化当前未写章 |
| A5 大纲体检 | `review` | 诊断和可选补丁，不直接改纲 |
| A6 重订走向 | `calibrate` | 输出未写章 old/new 差异与连带影响 |
| 正文反推大纲 | `import-outline` | 只读正文，按原顺序反推，不改写历史 |

## A1：完整立项

1. 先列用户已提供与仍缺失的内容，不重复询问。
2. 只对影响主线成立的缺口提问，最多 3 个；其余作显式假设。
3. 核心冲突写人物目标与阻力；卖点必须对应可观察场景。
4. 检查故事发动机能否持续产生不同问题，不默认增加惨痛代价、倒计时或宿命。
5. 输出符合 A1 数量和字段约束的提案。

## A1+：单块建议与回填

1. 读取目标字段、所有已填线索、草稿和作者方向。
2. 只围绕目标字段生成候选，不越界补其他字段。
3. 每条候选可直接回填，包含具体内容；需要多条时沿不同创作轴发散。
4. 目标字段已有内容时，只有用户要求重规划才给替代，并说明与既有线索的兼容风险。
5. 确认回填后，标记受影响的下游字段为“待复核”；只重规划失效部分，不自动清空整份立项。

## A2：主线与分卷

1. 先写全书主线与结局方向，再拆卷。
2. 每卷明确职责、目标、可重复单元、高潮、卷尾入口和预算。
3. 卷间至少在关系、信息、舞台、机制应用或问题类型之一上升级。
4. 按 `references/volume-budget.md` 检查总章数和总字数，不把章级事件提前写入本阶段。

## A3：卷章纲

1. 只处理 `volumeIndex` 指定卷；跳过已写章，新章排在已有章之后。
2. 每章给可执行 hooks、核心冲突、转折或信息增量、落点和目标字数。
3. 每章至少在任务、信息、人物决定、关系或情绪期待之一上产生增量。
4. 允许日常和状态维持章，但连续重复同一功能时合并或改变结果。
5. 首卷按 `story-golden-opening` 的承诺兑现原则检查，不机械分配三章职责。

## A4：章细纲

1. 读取当前章、所属卷、相邻章、出场人物、已发生事实和伏笔。
2. 把章纲展开为 3—6 条可执行 hooks，写清触发、选择和结果。
3. 在 `continuityNotes` 记录视角、时间、伤势、认知、物件和伏笔风险。
4. 不提前揭露后文底牌，不借细化增加新主线；已写章直接拒绝生成。

## A5：体检

1. 有文件输入时先运行：

```bash
node scripts/check-plan-health.js --file=<json>
```

2. 有伏笔对账输入时再运行可用的一致性脚本；脚本不可用时明确说明，不假装执行。
3. 模型只补动机、因果、重复、升级、关系状态等判断，避免重复报告同一问题。
4. 每项问题给位置、severity、合法 type、说明、建议；补丁只含允许字段且只指向未写章。
5. “连续低强度”不直接等于拖沓，必须证明缺少增量或重复。

## A6：按已写事实重订

1. 先标记已写/未写边界，已写章不进入候选补丁。
2. 提取已写正文已经改变的事实、人物认知、关系和伏笔，不以旧纲覆盖正文。
3. 只对确需变化的未写章输出 `oldHooks → newHooks`，说明原因和 rippleEffects。
4. 优先最小调整；作者新方向与已写事实冲突时先列为冲突，不擅自改历史。
5. 回填后再次检查相邻章、卷尾和后续依赖，必要时生成下一轮单块提案，不一次跨阶段执行。

## 校验与落库边界

- 需要结构校验时运行 `node scripts/validate-proposal.js --stage=<stage> --file=<json>`。
- 校验失败先修复 JSON，不落库；服务层修复失败时报告失败原因。
- 未收到系统写回成功结果，不宣称“已保存”“已回填”。

# 小说模板

## 模板边界

- 模板提供结构与起步提案，不是自动替作者决定整本书。
- 从参考作品拆出的模板必须先经 `story-deconstruct` 完整脱敏，只能含抽象写法，不含原书设定与事件链。
- 从作者自己的旧作创建模板时，区分可复用结构与新书必须重新设计的素材。
- 应用模板不得覆盖用户已经填写的书名、简介、人物、禁忌和已确认规划。

## 创建模板

1. 确定模板名称、适用题材、目标读者和使用边界。
2. 提炼核心读者承诺与可重复故事发动机。
3. 角色只定义功能、欲望和关系接口；专有姓名按用途保留或抽象化。
4. 世界锚点只保留能驱动事件的规则，避免百科堆积。
5. 主线分卷写功能与状态变化，不写死每一章。
6. 开篇骨架写承诺兑现、主角选择和章尾功能，不机械固定三章职责。
7. 附 2—3 个原创示例场景，验证模板确实能生成故事。

## 应用模板

1. 读取当前作品已填内容和模板版本。
2. 先展示差异：保留项、拟补空项、冲突项、需要作者选择项。
3. 只向空字段填入提案；冲突时不静默覆盖。
4. 作者确认后再写回，并将结果视为草稿，需要继续人物化和原创化。
5. 写回后检查是否残留模板占位符、原作品专名或与本书矛盾的关系。

## 输出契约

```markdown
# 模板元数据
- 名称 / 版本 / 题材 / 读者 / 来源与脱敏状态
# 读者承诺与故事发动机
# 角色功能与关系接口
# 世界锚点
# 主线与分卷骨架
# 开篇兑现骨架
# 原创示例场景
# 应用边界与禁忌
```

若项目要求固定 JSON 类型，映射到现有类型，不自行添加无法落库的字段。

## 完成报告

分别列出实际保留、填入、跳过和冲突项。只有系统成功保存后才称“模板已创建”或“已应用”。

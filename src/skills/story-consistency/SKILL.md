# 一致性审查

## 证据优先级

1. 已写正文中的明确事实。
2. 当前追踪状态、人物状态和时间线。
3. 已确认的章节摘要与人物/世界设定。
4. 大纲中的未来规划。

旧纲、未写章摘要和模型推断不能覆盖正文。不同来源冲突时列出冲突，不擅自选一个当真相。

## 流程

1. **确定范围与基准章**：记录实际读取了哪些章节、摘要和状态；抽样审查不能声称全书无冲突。
2. **建立事实账**：人物身份、位置、伤势、能力、资源、物件归属、关系状态和各自知道的信息。
3. **排时间线**：记录故事时间、章节顺序、持续时长、旅行与并行事件，区分明确日期和推测。
4. **核对人物行为**：OOC 必须同时给出人物既有动机/选择和当前反常行为；有充分新触发时不算 OOC。
5. **核对信息差**：人物是否引用了自己不可能知道的事实，或读者已知被误写成角色已知。
6. **核对伏笔**：埋设、阶段增量、回收和失效是否一一对应；回收是否改变行动或理解。
7. **给最小修复方向**：优先改未写章或后续承接；已写章只报告，不直接改。

## 确定性伏笔脚本

仅当章节使用 `[F-id 埋设]` / `[F-id 回收]` 标记时运行：

```bash
node scripts/check-foreshadow-parity.js <chaptersDir>
```

该脚本只能检查上述显式标记，不能理解项目数据库中的全部伏笔。没有标记或目录不适用时，明确“未执行有效脚本校验”，改做人工对账。

## 输出

| 位置 | 严重度 | 类型 | 事实 A | 事实 B | 判断依据 | 最小修复方向 |
|---|---|---|---|---|---|---|

- `blocking`：明确硬冲突，导致事件无法成立或正文无法衔接。
- `warning`：动机、认知、时间或伏笔存在明显问题，但仍需语境确认。
- `info`：可能缺铺垫、信息不足或可选优化。

另附“未覆盖范围”和“需要作者确认的两种解释”。默认不输出替换正文。

## 验收

- 每个 blocking 是否都有两处可定位证据，而非凭印象？
- 是否把作者刻意安排的误导、不可靠叙述或人物撒谎误判为设定冲突？
- 是否区分“尚未回收”与“已经失控”的长期伏笔？

# 单章创作流水线

## 目标

把“一次生成整章”拆成可审阅阶段，避免架构与正文混杂、问题稿自动下传、润色误改事实和未保存却宣称完成。默认一次处理一章。

## 输入

- 作品定位、目标字数、视角和文风约束。
- 当前卷纲、本章章纲与 hooks。
- 上一章结尾、相关摘要和当前追踪状态。
- 出场人物、相关规则、活跃伏笔和作者本轮要求。

缺少会改变事实的关键输入时先补齐；不要用模型猜测替代项目状态。

## 阶段 1：架构卡，不写正文

输出：

```markdown
- 本章承诺与目标：
- 主视角 / 时间 / 地点 / 在场人物：
- 必须覆盖的 hooks：
- 场景推进：触发 → 选择 → 结果
- 信息差：主角 / 他人 / 读者各知道什么
- 事实锚点：伤势、认知、物件、伏笔、关系状态
- 章末新状态与下一章待兑现事项：
- 禁止提前揭露：
```

检查章纲与已写事实是否冲突；冲突时停止并请求决定。

## 阶段 2：正文

1. 只根据架构卡和已确认资料写完整正文。
2. 覆盖全部 hooks，保持人物声音和视角边界。
3. 每个重要对白或行动产生即时后果；章末形成实际新状态。
4. 不在正文混入架构卡、质量说明、占位符或“以下是正文”。

## 阶段 3：确定性连贯性门禁

检查工具可用时运行项目检查，并保留行级 findings；不可用时明确标为人工检查，不伪造脚本结果。

重点检查：
- 必要 hooks 缺失、章纲与正文主语错位。
- 重复触发已结束事件、死人复活、伤势或位置跳变。
- 视角越权、认知矛盾、物件无来源。
- 复读、截断、占位符和工程指令泄漏。

`blocking` 必须返回阶段 1 或 2 修复；`warning/advisory` 结合语境判断，不为追求零提示破坏正常表达。

## 阶段 4：表达修订与质量检查

1. 冻结剧情事实、人物选择、伏笔与章末状态，只处理表达问题。
2. 按 `story-deslop` 清理解释腔、模板句、重复反应和节奏单一。
3. 有作者文风契约时做第二次改句，让句子贴近作者样本，但不复制样本文字。
4. 质量工具返回失败时不得显示“门禁通过”；分数和命中数只是辅助，不承诺 AI 率或真人比例。
5. 结构问题不得在润色阶段偷偷修补，退回对应阶段。

## 阶段 5：作者审批

在以下情况暂停：
- 大纲定稿后首次写正文。
- 黄金开篇、卷末、人物重大转向或事实变更。
- 任一 blocking 未解决。
- 作者要求逐阶段确认。

给作者展示必要正文和未解决项，不用长篇过程日志淹没正文。

## 阶段 6：保存、追踪与快照

工具可用且作者确认后：
1. 按项目协议写回完整正文。
2. 提交章节摘要、出场人物、实际覆盖 hooks、伏笔和状态变化。
3. 需要版本保护时创建流水线快照。
4. 只有各工具成功返回后才报告完成；部分成功时明确列出已完成和失败阶段。

## 批量原则

多章请求逐章重复完整流水线。下一章必须读取上一章实际定稿，不使用批量任务开始时的旧状态。任一关键门禁失败或作者暂停时，不自动继续后续章节。

# 小说导入与续写恢复

## 边界

- 用于作者拥有或获授权处理的作品；分析外部参考书的写法时使用 `story-deconstruct`。
- 原始文件只读，导入失败不覆盖原稿。
- 自动章节切分、人名识别、人物关系和伏笔提取都是候选结果，需按可信度标注。
- 工具不可用时只输出导入提案，不宣称已创建项目或更新数据库。

## 1. 预检

1. 确认文件、编码、长短篇、目标作品和是否允许写入。
2. 统计章节标记、总字符、可能的卷标记和异常格式。
3. 检查是否已有同名作品或既有正文；存在时先给冲突处理方案，不直接覆盖。
4. 短篇按单篇/少量场景处理，不强套长篇分卷与追踪流程。

## 2. 解析与校验

1. 按明确卷章标题切分；无卷标记时不擅自宣称原书分卷结构，临时分组必须标为可调整。
2. 保留章节原顺序、标题和完整正文，记录空章、重复章号、异常短章和无法识别片段。
3. 导入后对比章节数与字符量，抽查首章、中段、末章和边界章，防止截断。
4. 无章节标记的短篇按单章处理；不要因篇幅长就伪造章节。

## 3. 分层恢复事实

按块处理，避免一次性把全书塞进上下文：

1. **逐章纪要**：使用 `story-chapter-summary` 的事实契约。
2. **人物候选**：姓名、首次出场、目标、关系、当前状态；自动人名列表只作候选，合并昵称前需证据。
3. **时间线与认知**：只记录正文明确或可合理推断的内容，推断需标记。
4. **伏笔与未结事项**：区分长期未收、已收和可能只是普通细节。
5. **卷级/全书导航**：使用 `story-summarize` 聚合，不让全书摘要覆盖逐章事实。

每块完成后保存可复核结果；失败块可重跑，不必重导整本书。

## 4. 续写就绪检查

- 当前最后一章和下一写作位置明确。
- 上一章结尾、主要人物当前状态、活跃伏笔和时间线可用。
- 旧稿没有明确大纲时，可生成 `import-outline` 反推提案；它只是恢复规划，不修改历史。
- 缺失、冲突和低置信结果已列出。
- 作者确认后再进入 `story-continue`、`story-agent-write` 或 `story-plan-workspace` A6。

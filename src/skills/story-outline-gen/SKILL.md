# 大纲生成

## 总原则

- 先确认作者已经确定的事实与禁忌，不用“更完整”为理由改写。
- 一次只处理一个层级：主线 → 分卷 → 剧情单元/章纲 → 单章细纲。作者只问某层时，不自动展开下一层。
- 大纲是写作合同，但不是每章都必须高潮、反转或强钩子的公式。
- 已写正文是事实来源；调整已写章只给诊断，不直接改写历史。

## 分层流程

### 1. 全书主线

写清主角长期目标、核心阻力、主要关系或信息线、结局方向，以及可重复的故事发动机。检查中期是否仍有新类型的问题，而不是只提高敌人数值。

### 2. 分卷

每卷给出：独立职责、卷目标、主要单元、关键选择、卷末状态变化、下一卷入口和篇幅预算。卷间至少在关系、信息、舞台、能力应用或问题类型之一上发生实质变化。

### 3. 剧情单元与章纲

先划分“一个矛盾从出现到产生结果”的单元，再分章。每章至少有一项增量：
- 外部任务得到结果；
- 新事实改变理解；
- 人物作出新决定；
- 关系进入新状态；
- 情绪形成等待或回证。

允许低压、日常和状态维持章，但删掉后完全不影响后续时应压缩或合并。

### 4. 单章细纲

使用场景推进卡：

```markdown
- 本章承诺：标题/上一章让读者期待什么
- 主视角与当前目标：
- 具体阻力：
- 出场人物及各自目标：
- 必须承接的事实、伤势、认知、物件和伏笔：
- 场景 1：触发 → 选择 → 即时结果
- 场景 2（如需要）：如何产生不同功能，而非重复场景 1
- 本章新增事实：
- 情绪或关系新基线：
- 章尾待兑现事项：行动 / 信息 / 选择 / 后果，按需选择
- 目标字数：遵从作者或平台要求
```

## 信息差与伏笔

为秘密记录“谁知道、谁误解、读者知道什么、何时揭示、揭示后改变什么”。揭示必须改变行动或关系，不能只增加百科信息。伏笔区分短期、中期、长期，短钩及时回收，长钩持续提供增量。

## 输出与停靠

只输出当前请求层级的提案和待确认项。作者说“先做大纲”时，不大规模写正文；需要正文时由作者指定章节，再交给 `story-agent-write` 或 `story-chapter-pipeline`。

# 全书导航总结

## 流程

1. 读取章节纪要，必要时用正文核对冲突与缺失；记录实际覆盖范围。
2. 以已写正文为事实基准，合并重复事件，保留主线阶段结果和重要关系/认知变化。
3. 按真实卷结构聚合每卷主题、主线和卷尾待处理问题；未写卷不写“已发生”总结。
4. 从项目当前章节确定位置，不根据输入最后一行猜测。
5. 下一步方向只写最近可执行的任务，并兼顾已有伏笔和人物状态。
6. 只输出约定 JSON。人物弧、世界演化等详细分析若作者需要，另开任务，不塞进当前 schema。

## 强制输出契约

必须且只能输出以下 JSON，不要 Markdown 代码块或解释：

```json
{
  "novel_summary": "不超过100字、反映当前已写进度的作品概述",
  "volume_summaries": [
    {
      "volumeId": "来自项目资料的卷ID",
      "title": "卷标题",
      "theme": "本卷核心问题或情绪",
      "mainPlot": "本卷已发生主线的3-5句概括",
      "endingHook": "卷尾已经形成并指向后续的问题"
    }
  ],
  "current_position": {
    "volume": 1,
    "chapter": 1,
    "title": "当前章节标题"
  },
  "next_direction": "不超过50字、具体可执行的下一步方向"
}
```

## 约束

- `volumeId` 必须来自项目资料，无法取得时先请求资料，不伪造 ID。
- 卷尚未写完时，`endingHook` 写当前已形成的待处理问题，不冒充最终卷尾。
- 正文与旧摘要冲突时以正文为准，并在任务外部可说明冲突；当前 JSON 不添加额外字段。
- 下一步不提前泄露作者未确认的未来规划，不写空泛“继续推进主线”。
- 只有写回工具成功返回后，才能宣称知识库已经刷新。

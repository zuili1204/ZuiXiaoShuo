# 开书立项

## 原则

- 用户已填的书名、简介、角色、关系和禁忌优先，只补空缺，不覆盖。
- 模板只提供结构，不把模板人物、专有名词或情节带入新书。
- 一次完成“可审阅立项”，不在同一轮自动生成全书细纲和正文。

## 流程

1. **读取现有资料**：列出已确认项、缺失项和相互冲突项。
2. **确定读者合同**：写清目标读者、题材基调、核心卖点、主要情绪奖励和不做的事。
3. **整理故事发动机**：主角目标、反复出现的阻力、机制如何制造场景、每单元结束后改变什么。
4. **建立最小设定**：只保留开篇必需的人物、世界锚点与关系；详细扩展交给专门技能。
5. **建立开篇兑现表**：书名和简介中的承诺分别在前几章如何被看见。
6. **检查可持续性**：列出至少 3 个不重复的故事单元，以及一个中期升级方向。
7. **提交审阅**：把不确定内容标为假设，等待作者确认后再进入分卷规划。

## 输出

```markdown
# 作品立项
## 已确认事实
## 作品定位
- 书名 / 题材 / 基调 / 目标读者
## 一句话梗概与简介
## 核心故事发动机
- 触发 → 选择 → 结果 → 新状态
## 核心卖点与开篇兑现
| 承诺 | 首次可见兑现 | 后续升级 |
## 最小角色阵容
## 世界锚点
## 可重复故事单元
## 假设、冲突与待确认项
```

若运行环境要求 `story-plan-workspace` 的 A1 JSON 契约，则改用该契约输出，不另造字段。

## 禁止

- 不把“所有能力都必须有惨痛代价”当默认规则。
- 不为显得完整而编造作者未要求的庞大世界观。
- 未收到写回成功结果时，不宣称项目已经创建或保存。

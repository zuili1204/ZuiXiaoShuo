# 跨章上下文召回

## 目标

只装入“不知道就会写错”的资料，并保留事实来源与新旧边界。召回不是把整本书和全部历史对话塞进提示词。

## 来源优先级

1. 当前作者指令和当前章 hooks。
2. 已写正文、上一章结尾和当前追踪状态。
3. 已确认的人物、规则、卷纲与章节摘要。
4. 相关历史片段和知识库导航。
5. 未写章规划只作方向，不作既成事实；当前章旧稿摘要不得覆盖本次写作目标。

## 流程

1. **构造查询**：组合当前章任务、出场人物、相关物件、活跃伏笔和待兑现事项，不用空泛的“前文”。
2. **先取确定资料**：当前章、上一章、人物状态、时间线、相关设定和当前 hooks。
3. **再做相关检索**：按任务检索历史章节；项目当前默认可取 top-8，实际数量以运行环境和预算为准，不把数量当固定合同。
4. **去重与消解冲突**：正文与摘要重复时优先正文；旧纲与正文冲突时保留正文并标旧纲失效。
5. **按预算裁剪**：优先保留当前任务、状态、场景卡、上一章和伏笔；文风、历史对话与泛相关资料最后装。
6. **记录覆盖范围**：列出实际使用的章节/资料、缺失项和冲突项，便于排查“为什么写错”。

## 任务侧重

- 续写：上一章结尾、当前 hooks、人物状态、活跃伏笔、下一章承诺。
- 审查：目标正文、同人物历史选择、相关时间线和原始设定。
- 修订：目标段前后文、被改事实的影响范围、需要保留的作者文风。
- 久别人物：当前动态状态优先，静态人物卡补充声音与长期动机。

## 输出给写作 Agent 的上下文包

```markdown
# 当前写作目标
# 已确认事实与上一章承接
# 出场人物当前状态与认知
# 相关规则与活跃伏笔
# 相关历史证据（含章节来源）
# 文风约束
# 缺失、冲突与禁止使用的旧资料
```

不要向最终正文输出该上下文包。召回工具未实际运行时，不声称已检索数据库或向量索引。

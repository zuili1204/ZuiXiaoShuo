# 网文表达修订

## 核心边界

1. 只改“怎么说”，不改“说什么”。人物、事件、时间、关系、伏笔、设定、信息揭示和章末状态默认冻结。
2. “像 AI”不是语法错误，也不是命中某个词就必须改。结合题材、人物和语境判断。
3. 不承诺“0% AI”“100% 真人”或通过某检测器，不故意加错字、乱标点、口误和网络梗。
4. 结构、动机和事实问题只标注，交回 `story-review` 或 `story-revision`，不在润色中偷改。

## 模式

- **只检测**：输出 findings 和语境判断，不改原文。
- **表达修订**：先扫描，再最小改写，最后复扫。
- **流水线门禁**：按调用方契约输出修订文本与真实检查结果；失败时不得写“通过”。

## 1. 准备事实锚点

在内部列出：出场人物、关键事件、必要信息、伏笔、关系变化、必须保留的物件和章尾待兑现事项。修订后逐项对账。

有作者样本或文风契约时同时读取，区分：
- 本书应有风格：视角、句长、对白习惯、叙述距离、人物声音。
- 通用表达问题：重复解释、过度工整、机械反应、无意义总结。
作者风格优先于通用偏好。

## 2. 扫描与诊断

文件模式且工具可用时，先运行：

```bash
node scripts/check-ai-patterns.js --check --fail-on=blocking <正文文件...>
node scripts/check-degeneration.js --check <正文文件...>
```

- 保留脚本行号、类型和 severity；脚本未运行时不得伪造结果。
- `blocking` 优先处理；复读、截断、占位符和工程词泄漏通常需要回到生成阶段重写，而非换词。
- `advisory` 必须读语境，正常对白、专有名词和有功能的句式可以保留。
- 需要完整模式说明时读 `references/anti-ai-writing.md`；词表只作提示，不作绝对禁令。

人工优先检查：
1. 作者跳出场景解释因果、评价人物或总结意义。
2. 同一信息、动作、情绪或爽点被连续复述。
3. 动作、表情、心理、吐槽同时堆在一个对白后面。
4. 否定铺垫、工整排比、万能比喻和书面套话反复出现。
5. 每段等长、每句等重，或全文被切成电报体。
6. 所有人物共享同一语气、口头禅和网络语言。
7. 结尾用“他知道/这一刻/从此”等总结替代实际待处理事项。

## 3. 最小改写

按以下顺序处理：

1. **先删无功能重复**：删掉后不影响事实、因果、伏笔和情绪的解释或复述。
2. **合并同一瞬间**：保留最准确的动作或信息，不把动作拆成监控步骤，也不把全文压成短句。
3. **把解释还给场景**：仅在原文已有动作、物件、对白或证据时重排呈现；不得新增事件链。
4. **保留人物声音**：普通“说”、自然虚词和简单句可以保留；不为了变化给每句加奇特动词。
5. **调整节拍**：短句用于反应和揭示，中长句用于因果和氛围；重点情绪处减少吐槽和解释。
6. **修正结尾**：删除无功能升华，保留原文已有的行动、信息、选择或后果。
7. **保护幅度**：不整段删除有叙事功能的内容；改动过大时说明原因并交作者复核。

## 4. 作者风格二次改句

有作者样本或风格契约时，在通用修订后再做一轮：
- 对照视角距离、句长变化、对白密度、内心呈现和幽默方式。
- 只迁移写法，不带入样本人名、设定、物件、情节或原句。
- 若样本风格与通用规则冲突，保留有证据的作者习惯，并记录为何保留。

## 5. 复扫与输出

文件落盘后按环境支持复扫检查脚本；需要标点工具时才运行 `normalize-punctuation.js`，并先确认其默认行为符合作者标点习惯，不做零容忍清理。

输出：
1. 修订后完整文本；流水线要求标记时使用调用方指定的 begin/end 标记。
2. 简短报告：实际修改类型、字数变化、仍 blocking 项、需人工复核项。
3. 只检测时不输出替换稿。
4. 文件写回只有成功后才宣称完成；工具失败时保留原稿并报告。

## 停止条件

同一轮已无实质问题即停止。连续两轮仍大面积重写，说明根因可能不在表达层，应停止去 AI 味并转结构诊断。
